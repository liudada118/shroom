# 压力感知软件技术处理流程文档（简版）

文档日期：2026-06-04  
文档用途：用更偏技术实现的方式说明软件运行时每个流程做了哪些处理。  
文档口径：不写产品目标、用户价值、优先级和验收表；只写处理链路、关键状态、输入输出和数据影响。

### 1. 应用启动与服务初始化

- Electron 主进程从 `index.js` 启动。
- 主进程先分配运行端口，包括前端端口、API 端口和 WebSocket 端口。
- 如果默认端口被占用，使用端口探测逻辑寻找可用端口。
- 主进程 fork 后端子进程 `server/serialServer.js`。
- 后端从环境变量读取实际端口、打包状态、资源路径、下载路径、串口缓存路径等运行参数。
- 后端初始化全局状态 `state`，用于保存当前串口、设备、实时帧、历史回放、对比和采集状态。
- 后端初始化 SQLite 数据库，并把数据库实例挂到运行态。
- 后端启动 Express API 服务。
- 后端启动 WebSocket 服务，用于推送实时帧、回放帧、对比帧、连接状态和设备状态。
- 后端启动成功后把实际端口回传给 Electron 主进程。
- 主进程加载前端页面，开发模式加载 Vite，打包模式加载 `client/build/index.html`。
- 前端通过注入端口或环境变量拿到 API 和 WebSocket 地址。

### 2. 配置加载与运行配置归一

- 后端读取加密系统配置 `config.txt`，解析当前系统类型。
- 读取设备缓存 `serial_cache.json`，用于 MAC 到设备类型的本地映射。
- 读取方向配置 `data_direction.json`，恢复坐垫、靠背等矩阵对象的方向状态。
- 读取压强配置 `pressure_config.json`，恢复：
  - `pressureFormulaFile`
  - `pressureFormulaProfile`
- 系统设置页读取后端系统配置，展示可视化默认值和压强计算参数。
- 可视化默认值会做归一处理：
  - `gauss=3`
  - `color=50`
  - `filter=10`
  - `height=150`
  - 噪点消除上限 `filter=200`
- 本地可视化缓存首次加载时会迁移旧默认值，但尽量保留用户手动调过的非默认值。
- 压强配置保存时，后端校验公式文件是否存在，并校验公式模块导出原生标定接口 `calculateBasePressure/getCalibrationInput/calculateWeightPointPressures/calculatePressureMetrics`、逐点接口 `master`，或成对导出旧版 `estimatePressure/estimateMaxPressure`。

### 3. 设备连接与识别流程

- 处理对象说明：
  - 本节的端口指硬件串口 COM 端口。
  - API 端口、WebSocket 端口、前端服务端口的占用处理属于应用启动阶段。
  - 串口连接的核心实现集中在 `SerialManager`。
- 连接入口：
  - 前端点击一键连接后，请求 `/connPort`。
  - 重新连接按钮请求 `/rescanPort`。
  - 手动断开按钮请求 `/stopPort`。
  - `/connPort` 用于完整一键连接。
  - `/rescanPort` 用于先释放旧串口资源，再重新走完整连接流程。
  - `/stopPort` 用于关闭所有串口并清空连接运行态。
- 前端状态拦截：
  - 前端维护 `connectState`。
  - `connecting`、`rescanning`、`connected` 状态下会拦截重复连接。
  - 连接中再次点击时，不再重复请求后端打开串口。
  - 前端连接请求设置 15 秒超时。
  - 请求超时、接口失败或后端返回失败时，状态进入 `failed`。
  - 失败后按钮文案切换为重新连接。
- 后端连接生命周期锁：
  - `/connPort` 和 `/rescanPort` 共用连接生命周期锁。
  - 进入连接任务时记录 `connectionTask`、`connectionTaskStartedAt`、`connectionMode`。
  - 如果已有连接任务且未超过最大生命周期，返回 `CONN_BUSY`。
  - 如果旧任务超过最大生命周期，释放陈旧任务后允许新的连接流程进入。
  - 后端总连接超时为 20 秒。
  - 连接成功、连接失败、连接超时和异常退出都会释放连接锁。
- 连接前资源清理：
  - `/connPort` 默认先执行串口资源清理。
  - 清理已存在的串口对象。
  - 移除 parser 监听器。
  - 移除 port 监听器。
  - 关闭仍处于打开状态的串口。
  - 清空 `parserArr`、`dataMap`、`macInfo`、`linkIngPort`、`portHistory`、`lastDataTime`。
  - 停止实时发送 timer。
  - 重置采样率相关运行态。
  - 这样避免旧连接残留影响新连接。
- 串口列表扫描：
  - 后端调用 `SerialPort.list()` 获取本机串口列表。
  - 扫描阶段设置 3 秒超时。
  - 如果扫描不到任何串口，返回 `NO_PORT`。
  - 如果扫描有串口但没有符合硬件特征的候选设备，返回 `NO_CH340`。
  - 候选设备优先按 CH340/WCH/USB 特征过滤。
  - 多个候选串口会逐个进入探测流程。
- 端口占用与锁定判断：
  - 候选串口打开失败时，后端先识别是否属于端口占用或端口锁定。
  - 识别依据包括错误信息中的 `busy`、`access denied`、`permission`、`denied`、`already open`。
  - 端口占用通常来自其他软件已经打开该串口。
  - 常见占用来源包括串口调试工具、旧版本采集程序、未正常退出的后台进程。
  - 端口锁定通常表现为系统拒绝访问、打开超时、串口对象创建失败或创建后立即异常关闭。
  - 端口被占用或锁定时，当前候选串口不继续做协议探测。
  - 后端记录该端口失败原因，并继续尝试其他候选端口。
  - 如果所有候选端口最终都因为占用或锁定失败，整体连接返回 `PORT_BUSY`。
  - 前端展示“串口被占用，请关闭其他程序后重试”。
- 波特率探测：
  - 后端从配置中读取候选波特率列表。
  - 对每个候选串口和候选波特率临时打开串口。
  - 临时打开时使用 `autoOpen: false`，由代码主动控制打开时机。
  - 打开成功后监听原始字节流。
  - 使用协议分隔符 `AA 55 03 99` 做滑动窗口匹配。
  - 第一次匹配到分隔符后，继续统计到下一次分隔符之间的帧长度。
  - 帧长度命中已知长度时，判定该波特率可用。
  - 已知长度包括 18、130、146、1024、1025、4096、4097。
  - 如果出现两次分隔符但长度不在已知列表，也允许作为可用候选，兼容可变帧长设备。
  - 如果只匹配到一次分隔符但探测超时，也允许进入后续稳定连接，由正式解析阶段继续校验。
  - 如果没有匹配到协议分隔符，则关闭临时串口并尝试下一个波特率。
  - 每次探测结束都会移除监听器并关闭临时串口。
  - 单个端口探测完成后等待 500 毫秒。
  - 所有端口探测完成后，如果存在可用端口，再等待 1 秒让系统释放串口锁。
- 波特率探测失败处理：
  - 单个端口所有候选波特率都失败时，记录为 `BAUD_FAIL`。
  - 探测阶段遇到端口占用或锁定时，记录为 `PORT_BUSY`。
  - 探测失败的端口不会进入稳定连接阶段。
  - 如果没有任何端口探测成功，整体连接按失败端口优先级返回错误。
- 稳定连接：
  - 波特率探测成功后，后端不复用临时串口。
  - 先关闭探测串口，再重新打开正式串口。
  - 正式连接使用确认后的端口、波特率和协议分隔符。
  - 正式连接最多重试 3 次。
  - 每次重试间隔 500 毫秒。
  - 单次正式打开超时为 2 秒。
  - 正式打开成功后创建 `DelimiterParser`。
  - 串口对象与 parser 绑定后，才进入设备识别阶段。
- 稳定连接失败处理：
  - 正式打开阶段如果识别为占用或锁定，记录为 `PORT_BUSY`。
  - 其他打开失败记录为 `OPEN_FAIL`。
  - 当前端口关闭并移除运行态。
  - 后端继续尝试其他已探测成功的端口。
- 设备大类推断：
  - 后端根据探测出的波特率映射设备大类。
  - 设备大类用于决定后续识别策略。
  - 坐垫、脚垫类设备进入 MAC 读取和授权流程。
  - 手部设备先按 `hand` 类型建立实时解析，再异步尝试读取 MAC。
  - 无法推断设备大类时，记录为 `TYPE_UNKNOWN` 并关闭当前串口。
- 运行态初始化：
  - 稳定串口打开成功后写入 `parserArr`。
  - 写入正式串口对象、parser、波特率。
  - 在 `dataMap` 中创建当前端口的数据对象。
  - 写入 `deviceClass`、`baudRate`。
  - 初始 `type` 为空。
  - 初始 `premission` 为 false。
  - 写入 `lastDataTime`，用于后续僵尸设备判断。
  - 更新 `portHistory`，记录当前活跃串口。
- 设备 MAC 读取：
  - 坐垫和脚垫类设备必须读取 MAC。
  - 后端通过正式串口发送 AT 指令读取 Unique ID。
  - AT 指令按固定间隔重复发送。
  - 读取阶段监听原始串口数据，不依赖分隔符 parser。
  - 读取到 `Unique ID` 后继续收集短时间文本，解析 Unique ID 和版本号。
  - MAC 读取阶段超时为 3 秒。
  - 读取不到 Unique ID 时，记录为 `MAC_FAIL`。
  - MAC 失败的端口会立即关闭并从运行态移除。
- 设备类型识别：
  - 后端先根据 Unique ID 查询本地 `serial_cache.json`。
  - 本地缓存命中时直接得到设备类型，并视为本地授权通过。
  - 本地缓存未命中且授权模式为在线时，再请求在线设备服务。
  - 在线识别返回设备类型和授权状态。
  - 在线识别成功时，设备类型会写回本地缓存。
  - 本地模式下缓存未命中，则要求用户先在 MAC 配置中添加设备。
- 类型与授权校验：
  - 未识别到设备类型时，记录为 `TYPE_UNKNOWN`。
  - 在线授权不通过时，记录为 `AUTH_FAIL`。
  - 类型未知或授权失败的设备会立即关闭当前串口。
  - 对应 `parserArr`、`dataMap`、`lastDataTime`、`macInfo` 都会同步清理。
  - 只有类型识别成功且授权通过的设备，才允许进入实时数据链路。
- 数据监听绑定：
  - 设备通过校验后绑定 parser 的 `data` 监听器。
  - 监听器负责把分隔后的数据帧交给实时帧解析逻辑。
  - 此时才广播 `deviceUpdate`。
  - 此时才允许后续采集模块使用该端口数据。
- 部分成功处理：
  - 多个候选设备连接时，单个设备失败不会直接终止全部连接。
  - 成功的端口进入 `connectedPorts`。
  - 失败的端口进入 `failedPorts`。
  - 只要至少一个端口连接成功，整体返回 `success: true`。
  - 返回结果里同时包含成功端口和失败端口。
  - 如果所有端口都失败，再按失败优先级返回整体错误。
- 整体错误优先级：
  - 多个端口都失败时，后端按优先级挑选最终错误。
  - 优先级依次为 `PORT_BUSY`、`MAC_FAIL`、`TYPE_UNKNOWN`、`AUTH_FAIL`、`OPEN_FAIL`、`BAUD_FAIL`。
  - 这样前端优先展示最需要用户处理的原因。
- 结构化错误返回：
  - 后端错误统一包含 `code`。
  - 后端错误统一包含 `stage`。
  - 后端错误统一包含用户可读的 `message`。
  - 后端还会保留内部 `detail` 便于排查。
  - 常见阶段包括 `lock`、`scan`、`filter`、`detect_baud`、`open_port`、`mac`、`type_resolve`、`auth`、`timeout`、`cleanup`。
- WebSocket 进度同步：
  - 连接开始清理时广播 `connectProgress: cleaning`。
  - 波特率探测时广播 `detecting_baud`。
  - 正式打开时广播 `connecting`。
  - MAC 读取时广播 `getting_mac`。
  - 类型识别时广播 `resolving_type`。
  - 单端口连接成功时广播 `connected`。
  - 整体完成后广播 `connectResult`。
  - 读取到 MAC 信息后广播 `macInfo`。
- 失败清理：
  - `/connPort` 失败后广播失败版 `connectResult`。
  - 后端执行一次全量串口资源清理。
  - 清理所有打开过的串口、parser、监听器、缓存和实时发送 timer。
  - 写入 `lastConnectionError`。
  - 释放连接锁。
  - 前端根据错误信息进入失败状态并展示提示。
- 重连处理：
  - `/rescanPort` 先进入同一把连接生命周期锁。
  - 重连开始后广播 `rescanProgress: cleaning`。
  - 后端完整释放旧串口、parser、监听器、缓存和发送定时器。
  - 清理后等待 1 秒，给操作系统释放串口锁。
  - 然后调用完整连接流程重新扫描、探测、识别、授权和绑定数据监听。
  - 重连成功后广播 `rescanProgress: done`。
  - 重连失败后广播 `rescanProgress: failed` 和失败版 `connectResult`。
- 断开处理：
  - `/stopPort` 调用全量串口资源清理。
  - 清空连接锁。
  - 清空连接任务开始时间。
  - 清空连接模式。
  - 后端同时退出历史或对比回放上下文。
  - 前端清空设备在线状态、MAC、数据质量、实时矩阵、COP、历史图表、回放状态和采集状态。
- 连接成功后的后端状态切换：
  - `/connPort` 成功后退出历史回放状态。
  - 清理历史播放缓存。
  - 停止历史播放 timer。
  - 立即推送一次实时帧。
  - 延迟再推送一次实时帧，避免前端刚切回实时模式时拿不到最新数据。

### 4. 实时数据接收与帧解析

- 原始字节接收：
  - 串口 `data` 事件收到的是连续字节流，不一定刚好等于一帧。
  - 后端先把收到的数据追加到缓冲区。
  - 缓冲区用于处理半帧、粘包、多帧连续到达等情况。
- 分隔符切帧：
  - 后端按协议分隔符从缓冲区中查找候选帧边界。
  - 找到完整边界后才取出候选帧。
  - 分隔符前后不足一帧的数据继续留在缓冲区，等待下一次串口数据补齐。
- 帧完整性校验：
  - 校验候选帧长度是否满足当前设备协议。
  - 校验有效数据段是否能还原出期望点数。
  - 长度不对、分隔符异常、点数不匹配都会记为坏帧。
  - 坏帧会被丢弃，不继续进入矩阵转换。
- 设备解析函数选择：
  - 后端根据已识别的设备类型选择对应解析函数。
  - 不同设备的点数、宽高、方向、数据位宽可能不同。
  - 解析函数负责把协议数据段转换成一维压力点阵数组。
- 一维点阵清洗：
  - 解析后先得到原始一维数组。
  - 对数组长度做二次校验。
  - 对异常值做基础过滤，避免无效值影响后续矩阵和采集。
  - 如果数组长度和设备规格不一致，当前帧按矩阵错误处理。
- 矩阵转换：
  - 后端根据设备类型、系统类型和矩阵 key，把一维数组转换为二维矩阵。
  - 坐垫、背垫、选区等不同业务矩阵使用不同的宽高规格。
  - 需要旋转或翻转的设备，在矩阵标准化阶段继续处理。
- 矩阵元信息写入：
  - 每帧都会补齐 `matrix_key`。
  - 写入 `matrix_width` 和 `matrix_height`。
  - 写入 `point_count`，用于后续采集、导出、报告校验。
  - 元信息让后续模块不再反推当前帧属于哪类矩阵。
- 实际采样率计算：
  - 后端记录每帧到达时间。
  - 按相邻帧时间差计算实际采样率 HZ。
  - 硬件返回的 HZ 只作为记录和校验，不作为唯一可信来源。
- 帧质量统计：
  - 统计总帧数。
  - 统计坏帧数。
  - 统计连续坏帧数。
  - 计算坏帧比例。
  - 记录最近错误原因。
  - 记录最近收包时间。
- 状态判断：
  - 单个坏帧不会打断实时流。
  - 连续坏帧超过阈值时，标记为数据异常。
  - 长时间没有新帧时，标记为离线或连接异常。
  - 矩阵尺寸错误时，标记为矩阵异常。
- 实时输出：
  - 通过校验的帧会组成标准实时数据对象。
  - 实时数据对象包含矩阵、设备类型、矩阵 key、时间戳、HZ、质量状态。
  - 后端再通过 WebSocket 或接口推送给前端实时页面。
- 入库过滤：
  - 只有在线、设备正常、矩阵正常的帧才允许进入采集入库。
  - 离线帧、设备错误帧、矩阵错误帧只用于状态提示，不写入采集文件。
  - 这样可以避免历史数据、报告和导出结果混入异常帧。
- 异常恢复：
  - 临时坏帧只丢弃当前帧。
  - 连续异常会保留错误原因，供前端提示和排查。
  - 串口断开或重连后，缓冲区和连续坏帧计数会重新初始化。

### 5. 矩阵标准化处理

- 原始设备帧保留为排查数据，不直接给展示和统计使用。
- 业务矩阵会先经过设备类型对应的线序转换。
- `endi-back` 等靠背矩阵按当前线序规则转换为前后端约定尺寸。
- 靠背矩阵在线序转换和插值后保持原 ADC 数值，不执行靠背专属倍率；传感器差异完全由标定文件处理。
- 坐垫默认方向为顺时针 90 度并上下翻转。
- 旧方向缓存加载时会迁移到当前默认方向口径。
- 方向处理按当前矩阵 key 独立执行，坐垫和靠背互不影响。
- 方向处理后写入 `dataDirection` 和 `rotate_degree`。
- 如果开启预压力置零，后端使用当前帧减去置零基线，小于 0 的值归 0。
- 坐垫 `23×23 → 46×46`、靠背 `25×32 → 50×64` 的插值在线序映射阶段先完成；置零后对原生座椅和靠背统一将 `ADC<30` 归零，随后对完整矩阵执行标定。
- 标准处理器不追加位置掩码、压强曲线、分支、系数或逐点分配规则；固定 `ADC≥30` 门槛只负责形成统一的标定有效输入。
- 每帧 `calibrationDiagnostics` 记录门槛前正数点、有效点、TOP46 选点数与均值、最大 ADC、标定分支及压强结果。
- 噪点消除、高斯润滑和相干参数仅保留给旧接口、配置与历史快照，不改变业务基准矩阵。
- 颜色和高度等纯显示参数不污染业务基准矩阵。

### 6. 前端实时接收与渲染

- 前端通过 `useWebSocket` 建立 WebSocket 连接。
- WebSocket 兼容 JSON 和 MessagePack 消息。
- 前端按消息字段分发：
  - `sitData`：实时数据
  - `sitDataPlay`：历史回放数据
  - `contrastData`：数据对比数据
  - `macInfo`：设备信息
  - `dataQuality`：数据质量状态
  - `connectProgress`：连接进度
  - `connectResult`：连接结果
- 实时矩阵进入 `useMatrixData`。
- `useMatrixData` 按当前系统类型和矩阵 key 处理矩阵。
- 处理结果写入 zustand store。
- 2D 数字视图、3D 点图、3D 模型和图表侧栏从 store 读取当前数据。
- 框选或回放状态变化时，可重算最近一帧统计，不必等待下一帧 WebSocket。

### 7. 工具处理流程

- 置零：
  - 前端点击置零后同步当前基线。
  - 后端采集和导出使用置零后业务矩阵。
  - CSV/XLSX 导出记录置零状态和置零时间。
- 翻转/旋转：
  - 前端修改方向后请求 `/setDataDirection`。
  - 后端保存到 `data_direction.json`。
  - 实时输出、采集入库、回放和导出都使用修正后的业务矩阵。
  - 采集中禁止继续修改方向。
- 框选：
  - 框选区域按矩阵坐标保存，不按像素保存。
  - 切换系统、坐垫、靠背时校验或清空不适用的框选区域。
  - 框选只影响分析范围，不控制采集范围。
  - 采集仍保存全量矩阵。
- 量尺：
  - 量尺按传感点距计算真实距离。
  - 最多保留 8 条。
  - 框选和量尺模式会锁定 2D 数字视图，避免缩放或拖拽导致坐标错位。
- 可视化调节：
  - 图像润滑、颜色、噪点、亮度等参数在前端和系统设置页保持同一默认值口径。
  - 可视化调节打开时按钮展示激活态。
  - Max 不在抽屉内编辑，只作为输入边界。

### 8. 数据采集流程

- 用户点击采集后，前端先弹出采集信息弹窗。
- 用户可填写数据名称和备注。
- 确认后前端请求 `/startCol`。
- 后端启动采集前校验：
  - 设备在线
  - MAC 已识别
  - 设备类型匹配
  - 授权通过
  - 当前不处于方向修改中
- 采集开始时记录当前方向、置零状态、采样参数和框选元数据。
- 采集过程中，实时定时器继续推送数据，同时把有效帧写入 SQLite。
- 入库前会跳过离线帧、设备错误帧、矩阵错误帧。
- 入库帧保留：
  - 时间戳
  - 矩阵数据
  - 设备 MAC
  - 设备类型
  - 方向信息
  - 置零信息
  - 矩阵元信息
  - 备注
- 采集开始和停止时都会读取当前框选 `brushInstance.rangeArr`。
- 当前框选按矩阵 key 转成 `{ regions: [...] }` 后写入 `remarks.select_json`。
- 用户不退出框选模式，也能在历史下载中导出框选区域数据。
- 停止采集时调用 `/endCol`。
- `/endCol` 成功后清空历史列表缓存。
- 如果历史抽屉已打开且处于本地历史页，前端重新请求 `/getColHistory`。

### 9. 历史回放流程

- 用户选择历史记录后，前端请求历史详情或回放接口。
- 后端从 SQLite 加载历史帧。
- 回放前校验每帧：
  - 是否存在矩阵
  - 矩阵长度是否正确
  - 点值是否为数字
- 异常帧会跳过并累计跳过数量。
- 连续异常超过阈值时停止回放并返回错误。
- 回放定时器按当前倍速逐帧推送 `sitDataPlay`。
- 支持倍速：
  - `0.5x`
  - `1x`
  - `2x`
  - `4x`
- 拖动进度条时，后端按 index 生成当前帧快照。
- 回放中框选会基于历史全量矩阵重新计算区域统计和曲线。
- 回放自然结束时，不立即清空当前记录和进度。
- 底部播放条保留在末帧，直到用户主动退出历史入口。
- 再次点击播放时，前端先把进度重置到第 0 帧，再启动后端回放。
- 退出回放时清理：
  - 最后一帧回放缓存
  - 历史曲线
  - COP 缓存
  - 回放状态
  - 历史框选 DOM
- 如果设备仍在线，退出后恢复实时推送。

### 10. CSV/XLSX 导入流程

- 用户上传 CSV/XLSX 后，前端请求上传接口。
- 后端先把文件保存到临时位置。
- 保存后立即校验文件结构。
- 校验内容包括：
  - 基础时间字段
  - 矩阵数据字段
  - 统计列
  - 矩阵长度
  - 点值是否为数字
- CSV/XLSX 兼容旧字段和新字段。
- XLSX 读取 raw cell value，修复科学计数法时间戳。
- 校验失败时删除临时文件并返回“数据有误”。
- 校验成功后加入本地导入列表。
- 导入列表按文件路径去重。
- 读取导入数据时，把 CSV/XLSX 转成历史回放可用帧结构。
- 导入数据不写入本地采集历史表。
- 导入数据可用于：
  - 回放
  - COP 报告
  - 数据对比

### 11. CSV/XLSX 导出流程

- 用户在历史数据中点击下载。
- 前端请求 `/download`，旧接口 `/downlaod` 保留兼容。
- 后端读取历史记录和历史帧。
- 导出字段选择只维护一套通用字段。
- 通用字段包括：
  - 时间戳
  - 设备 MAC
  - 最大压强
  - 最大压强坐标
  - 平均压强
  - 受力面积
  - 数据
  - 点数
  - 总压力
  - 备注
- 实际写文件时，后端把通用字段展开为靠背、坐垫和框选 1-4 的列。
- 示例列包括：
  - 靠背最大压强
  - 坐垫最大压强
  - 靠背框选1平均压强
  - 坐垫框选1受力面积
- 靠背和坐垫同帧数据写入同一行。
- 框选区域优先使用历史回放缓存或 `remarks.select_json`。
- 导出直接读取后端标准帧中的 `pressureArr` 和 `forceArr`；旧历史缺少当前标准矩阵时，先按当前公式文件和逐点归一化规则从原始 ADC 重算。
- 公式文件由 `pressureFormulaFile` 决定，最大值、平均值和总压力均从逐点结果聚合，不再单独调用 `estimateMaxPressure` 推算最大值。
- 导出文件名和对象字段使用公开名称，不暴露内部 `endi` key。

### 12. 数据对比流程

- 用户可从本地历史或导入数据选择 A/B。
- 前端记录每条数据的来源：
  - `history`
  - `csv`
- 启动对比时，后端按每条数据自己的来源加载帧。
- 本地历史数据从 SQLite 加载。
- 导入数据复用 CSV/XLSX 解析后的回放帧。
- 如果来源字段缺失，但记录值能识别为存在的 CSV/XLSX 文件路径，后端按导入来源兜底处理。
- 对比前校验：
  - A/B 是否都存在
  - 数据是否为空
  - 矩阵 key 是否可归一
  - 矩阵尺寸是否可比
- 对比链路会把 `endi-back/back`、`endi-sit/sit` 归一为靠背/坐垫 key。
- 跨记录对比按时间轴取最近帧。
- 同记录时间点对比使用用户选择的 A/B 时间点。
- 差值矩阵使用 `B - A`。
- 指标差值使用显示值口径相减，避免浮点精度导致表格和显示不一致。
- 受压面积必须乘以传感点实际面积，不能只统计有效点数量。
- 对比页面展示：
  - A 图
  - 差值图
  - B 图
  - 指标差值
  - 当前帧进度
- 退出对比时清理对比状态，并恢复实时数据流。

### 13. COP 报告流程

- 用户可从本地历史或导入数据生成 COP 报告。
- 本地历史报告读取 SQLite 历史帧。
- 导入数据报告通过 `source=csv&fileName=...` 读取导入文件帧。
- 进入报告前，如果当前存在框选模板，前端把当前 `selectJson` 暂存到 `sessionStorage`。
- 报告请求优先使用显式传入的 `selectJson`。
- 没有显式传入时，不默认套用采集时旧框选。
- 报告按传感面展示：
  - 靠背压力分布
  - 座椅压力分布
  - 靠背 COP
  - 座椅 COP
- 压力趋势、COP 偏移趋势和 COP 轨迹使用 ECharts。
- 框选区域的局部趋势图也使用 ECharts。
- 报告导出 PDF 时使用 Electron `printToPDF`。
- 打印样式会重置背景、尺寸和分页，避免 PDF 黑边。
- 点击返回时：
  - 前端清理回放状态
  - 清理历史曲线
  - 清理播放记录
  - 调用 `/cancalDbPlay`
  - 后端清理历史上下文
  - 恢复实时推送

### 14. 压强计算配置流程

- 后端 `PressureConfig` 统一读取和保存 `pressure_config.json`。
- 默认配置：
  - `pressureFormulaFile=point_pressure_calibration.js`
  - `pressureFormulaProfile=point_pressure_calibration`
- 旧配置中的 `backValueMultiplier` 会在归一化时丢弃，不能再改变靠背 ADC 或压强结果。
- 系统设置页请求 `/getPressureConfig` 读取当前配置和可选公式文件列表。
- 用户修改配置后，请求 `/setPressureConfig` 保存。
- 保存时后端校验：
  - 公式文件必须存在
  - 公式文件名必须符合规则
  - 当前原生标定公式必须导出 `calculateBasePressure`、`getCalibrationInput`、`calculateWeightPointPressures` 和 `calculatePressureMetrics`
  - 兼容公式也可导出逐点函数 `master`，或同时导出 `estimatePressure` 和 `estimateMaxPressure`
- 后端标准帧处理通过 `loadPressureFormula()` 动态加载公式文件，CSV/历史导出复用其结果。
- 公式文件按修改时间刷新缓存。
- 前端实时页和 COP 报告加载时读取压强运行配置。
- 前端把 `pressureFormulaProfile` 写入浏览器侧 `pressureMetrics`。
- 如果前端未知该 profile，则回退到默认公式版本。

### 15. 清理与恢复流程

- 手动断开设备时，前端清空：
  - 设备在线状态
  - MAC 信息
  - 数据质量状态
  - 实时矩阵
  - 历史曲线
  - COP 数据
  - 回放状态
  - 采集状态
- 后端 `/stopPort` 关闭串口后同步清理：
  - 历史回放状态
  - 对比状态
  - 回放 timer
  - 历史帧缓存
  - 对比帧缓存
- 回放退出、对比退出和报告返回都会清理历史上下文。
- 如果实时串口仍可用，后端恢复实时推送。
- 前端收到实时帧前会先清空上一帧历史缓存，避免历史数据残留到实时界面。

```text
应用启动
  -> 分配端口
  -> 启动后端子进程
  -> 初始化 SQLite
  -> 读取系统配置 / 设备缓存 / 方向配置 / 压强配置
  -> 启动 API 和 WebSocket
  -> 加载前端页面

连接设备
  -> 扫描串口
  -> 过滤 CH340
  -> 探测波特率
  -> 稳定打开串口
  -> 读取 MAC
  -> 识别设备类型
  -> 校验授权和类型
  -> 绑定数据监听

实时数据
  -> 原始字节分帧
  -> 校验帧
  -> 解析点阵
  -> 线序转换
  -> 坐垫/靠背矩阵插值
  -> 靠背乘数
  -> 方向修正
  -> 置零
  -> 有限值与非负归一化
  -> 按标定文件规则补齐完整 kPa 矩阵
  -> 压力换算
  -> 生成标准矩阵 payload
  -> WebSocket 推送
  -> 前端统计和渲染

采集数据
  -> 采集弹窗
  -> startCol 校验
  -> 记录方向 / 置零 / 框选元数据
  -> 有效帧入 SQLite
  -> endCol
  -> 刷新历史列表

历史回放
  -> 加载历史帧
  -> 校验坏帧
  -> 定时推送 sitDataPlay
  -> 前端复用实时渲染链路
  -> 播放结束保留进度
  -> 退出后清理历史上下文

导入数据
  -> 上传 CSV/XLSX
  -> 校验结构
  -> 路径去重
  -> 转换为回放帧
  -> 支持回放 / 报告 / 对比

  -> 选择通用字段
  -> 展开靠背 / 坐垫 / 框选列

  -> 计算 B-A

COP 报告

  -> 读取当前框选
  -> 按传感面计算统计和 COP

  -> printToPDF
  -> 返回后清理回放态并恢复实时
```

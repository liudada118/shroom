# 原始数据口径与未测项目

本目录对应《假人传感衣对接调整文档》§1 第 2 项和 §5.3（标定原始数据表）。所有表都由 `算法JS/seatBackrestPressure_v2.12.0.js` 对原始采集文件逐帧计算得到，复算方法见 `复算与测试/README_复算.md`。

## 1. 原始采集文件

| 部位 | sensorType | 文件数 | 每份内容 | 总帧数 |
| --- | --- | --- | --- | --- |
| 恩迪坐垫 | `endi-23x23` | 31（31 个放置位置） | 2 轮 × 5 档（1–5 块）× 20 帧 = 200 帧 | 6,200 |
| 恩迪靠背 | `new-backrest-32x25` | 44（44 个放置位置） | 2 轮 × 5 档 × 20 帧 = 200 帧 | 8,800 |

文件在 `原始采集/恩迪坐垫_31位置/` 和 `原始采集/恩迪靠背_44位置/`，原样交付，没有改动。逐份大小和 SHA256 见 `原始采集文件索引.csv`。

每份 CSV 保存了串口原始字节、插值前的原始物理 ADC、补偿前的插值 ADC 和帧元数据（时间戳等）。文件头里“实际总质量、砝码数量、放置位置”等标签列是空的，采集时没有填写。

## 2. 真值从哪里来

真值按采集规程推定，不是从文件标签读出的：

- 每份文件按时间顺序为第 1 轮 1→5 块、第 2 轮 1→5 块，每档 20 帧。第 k 帧（从 0 起）属于第 ⌊k / 100⌋ + 1 轮、第 ⌊(k mod 100) / 20⌋ + 1 块。
- 每档第 11–20 帧为放稳帧（`stable_frame = 1`），残差统计只用放稳帧。
- 每块砝码 1.625 kg，g = 9.8 m/s²，真值力 = 块数 × 15.925 N。
- 砝码底面直径 9 cm，面积 63.62 cm²。

## 3. §5.3 格式原始表

文件：`坐垫_砝码覆盖格原始表.csv`（49,800 行）、`靠背_砝码覆盖格原始表.csv`（53,600 行）。

| 列 | 含义 |
| --- | --- |
| sensorType | `endi-23x23` / `new-backrest-32x25` |
| row, col | 原生物理点坐标，行优先，左上角为原点（坐垫 23×23，靠背 32×25） |
| load_kPa | 该格承受的载荷压强 = 块数 × 15.925 N ÷ 63.62 cm² × 10 = 块数 × 2.5031 kPa |
| measured_adc | 该物理点的原始 ADC（未补偿） |
| repeat_index | 重复序号 = 轮次（1、2）；同一位置、同一块数每轮有 10 个放稳帧，用 sample_index（1–10）区分 |
| source_file, round, blocks, sample_index, frame_index, timestamp_ms | 追溯到原始文件的哪一帧 |
| cell_distance_mm | 物理点到推断砝码中心的距离 |
| coverage_basis | 覆盖格的判断依据，固定为 `inferred_adc_centroid_r45mm` |

**load_kPa 是按砝码实际接触底面积计算的，不是按整片传感器面积平摊的**（对接文档 §5.4）。

**覆盖格是推断的。** 采集时没有记录砝码放在哪些格上，所以按每轮放稳帧原始 ADC 的加权质心，取半径 45 mm（砝码底面半径）以内的物理点作为覆盖格。每轮（1–5 块全部放稳帧合计）的质心、覆盖格列表、覆盖格内 ADC 占整帧的比例见 `砝码覆盖格推断汇总.csv`（150 行）。覆盖格内 ADC 占比中位数：坐垫 0.81，靠背 0.76，说明有约 20% 的响应落在砝码底面以外（压力扩散），这也是估算面积随块数变大的原因。

这张表能满足 §5.3 的列格式，但它**不是**单格小压头标定数据：一块砝码同时压 11–18 个物理点，每个点的真实受力并不相同，不能直接用来拟合逐格 a、b。
